## Предметная область: Ветеринарная клиника

В клинику приходят питомцы, и их записывают на приём к врачам.
Есть два вида ресурсов:
1. **Питомцы (Pet)** — у них есть тип (кошка/собака), хозяин и статус вакцинации.
2. **Записи на приём (Appointment)** — привязаны к питомцу по `petId`, имеют врача, время и статус (`SCHEDULED`, `COMPLETED`, `CANCELLED`).

### Типы питомцев и логика
Сделал два типа с разным поведением:
- **Кошкам (CAT)** можно записываться к врачу без прививки.
- **Собакам (DOG)** без прививки записываться нельзя (при попытке вернётся 409 Conflict).

### Операции, меняющие состояние
Вместо обычного редактирования сделал отдельные эндпоинты:
- `POST /appointments` — запись на приём. Проверяет вакцинацию собаки, что время в будущем, и что врач не занят на это время.
- `POST /appointments/{id}/complete` — завершение приёма (только из статуса SCHEDULED).
- `POST /appointments/{id}/cancel` — отмена (нельзя отменить завершённый).

### Фильтрация
Списки поддерживают параметры в URL:
- `GET /pets?type=CAT` (или `?vaccinated=true`)
- `GET /appointments?status=SCHEDULED` (или `?vetName=Dr.House`)
